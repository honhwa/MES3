WinForms 控件初始化迁移规格（Designer-compatible）
=====================================================
目标：把每个 Form/UserControl 类别的「控件建立 + 静态属性 + 加入容器」搬进
      <ClassName>.Designer.cs 的 InitializeComponent()；
      动态逻辑留在 <原档>.cs 的 InitializeRuntime(...) / 既有 helper。
参考实作（务必先读，完全照抄其结构/命名/风格）：
      P:/github/MES3/SuperCapMES.WinForms/Forms/TpmExecuteForm.Designer.cs
      P:/github/MES3/SuperCapMES.WinForms/Forms/TpmExecuteForm.cs

【硬性规则】
1. .cs：类别改为 `public partial class X : Form`（或原本的 UserControl / 原可及性）。
   建构式只保留：
       InitializeComponent();
       InitializeRuntime(<原参数>);   // 若原码无任何动态逻辑，可省略
   其余 public/internal 属性、栏位、事件处理方法、巢状类别、helper 方法、
   商业逻辑、XML 注解「全部原样保留」，不得删改语义。
   原本 `private readonly Control _x = null!;` 之类的控件栏位整段删除
   （栏位改由 Designer.cs 宣告），但非控件状态栏位（bool/string/List/...）保留。
   using 保留在 .cs；Designer.cs 一律用完整限定名，不写 using。

2. .Designer.cs 结构（顺序照参考档）：
   #nullable disable
   // <auto-generated> 注解
   file-scoped namespace（与原档相同）
   `partial class X`（不写基底类别、不写存取修饰词）
   private System.ComponentModel.IContainer components = null;
   protected override void Dispose(bool disposing) { ... base.Dispose(disposing); }
   #region Windows Form Designer generated code
   private void InitializeComponent() { ... }
   #endregion
   所有控件栏位宣告（无初始值、无 readonly、无 null!）

3. InitializeComponent() 内「只允许」以下陈述形式（VS Designer 以 CodeDOM 解析，
   出现其它形式设计师会载入失败）：
   - this.components = new System.ComponentModel.Container();
   - this.<f> = new System.Windows.Forms.<T>(); 或 System.Drawing / System.ComponentModel 型别
   - this.<f>.<Prop> = <literal | enum | new System.Drawing.Size/Point/Padding/Font/Color |
                           new System.Windows.Forms.Padding/ColumnStyle/RowStyle |
                           new object[] { ... }>;
     自订 RGB 颜色一律写 VS canonical 形式：
       System.Drawing.Color.FromArgb(((int)(((byte)(R)))), ((int)(((byte)(G)))), ((int)(((byte)(B)))))
     已知色用 System.Drawing.Color.White / Gray / WhiteSmoke 等。
   - this.<f>.Items.AddRange(new object[] { ... });        // 仅静态项目
   - this.<f>.Controls.Add(this.<g>); 或 .Add(this.<g>, col, row);
   - this.<f>.ColumnStyles.Add(new ...ColumnStyle(...)); / RowStyles.Add(...)
   - this.<f>.SetColumnSpan(this.<g>, n); / SetRowSpan
   - this.<f>.Click += new System.EventHandler(this.Handler);  // 仅方法群，不可 lambda
   - this.<f>.SuspendLayout(); / ResumeLayout(false); / PerformLayout();
   - this.<表单属性> = ...;  this.Controls.Add(this.<f>);
   - 每个控件都要设 this.<f>.Name = "<f>";
   陈述顺序：所有 new → SuspendLayout → 属性与 Controls.Add → 表单属性 → ResumeLayout。

   【禁止】for / foreach / while / if / switch / try / return / throw / var /
           lambda(=>, (_,_)=>) / 字串插值 $"..." / ?. / ?? / null! /
           MesDatabase.* / 任何自订 helper 呼叫（AddRow、MakeGrid、MakeCard...）/
           任何非常值运算式（如 bottom.Width - 232、DateTime.Today、plan.XXX）/
           任何方法呼叫（上列白名单除外）。
   若原始码含 `Location = new Point(bottom.Width - 232, 10)`：
     原码在 bottom 加入 Controls「之前」求值，Panel 预设宽=200 → 常量 -32。
     改写为 this.btnOk.Location = new System.Drawing.Point(-32, 10);
     并加注解说明（参考档已有范例）。其它同型式子同理换算；无法判定者改放 InitializeRuntime 并保留原始运算式原样。

4. 动态逻辑（以下全部搬到 .cs 的 InitializeRuntime(...) 或既有 helper，原码逐行保留）：
   - 依赖建构式参数的 Text / Items / SelectedIndex / Value
   - MesDatabase.* 取数、foreach/for 建项、档案/网络/时间
   - lambda 事件：改成具名方法（方法本体放 .cs），
     并在 Designer.cs 用 `+= new System.EventHandler(this.<具名方法>)` 挂上
   - 字串插值、条件判断、?. / ??、工厂方法（MakeGrid/MakeCard/AddRow 等）
     工厂方法若只产生「静态」控件：请把产出改为 Designer.cs 的显式栏位 + 陈述；
     若含执行期资料：保留在 .cs，产生的控件不会出现在设计师中（可接受）。
   - 事件 handler 若原本用 `+= Handler` 方法群，直接放 Designer.cs。

5. 行为不变优先：不得顺手改 UI、不得改商业逻辑、不得改属性名称、
   不得改 public API。仅做档案拆分 + 必要具名化。

6. 一个 .cs 档含多个 Form 类别（AssistantFeedbackForms.cs、
   MaterialScrapForms.cs）→ 每个类别各建一个 <ClassName>.Designer.cs，
   两个类别都改成 partial，各自建构式呼叫自己的 InitializeComponent()。

7. 档案编码 UTF-8 without BOM、LF 或 CRLF 皆可（与既有档一致即可）。
   只动被指派档案；不得改 csproj、不得改其它档案、不得执行 dotnet build
   （主流程统一建置，避免 obj 目录竞争）。

8. 完成回报：列出「已建立的 Designer.cs」「已改写的 .cs」「搬到 InitializeRuntime 的项目」
   「发现的无法 Designer 化项目」。
