## 一、这一批解决了什么问题

前一批回答"缺料什么时候必须下单"，这一批回答另一半：**已经在库但快过期的料，现在该怎么办、花多少钱、谁有权批、留什么痕。**

三件事必须同时成立才叫"管控"：
1. **判得准**：不能只看"还剩几天过期"。剩 25 天但每天用 500 → 3 天就用完，不危险；剩 200 天但没人用 → 照样报废。
2. **有出口**：临期料只有三条路（提前排产消耗 / IQC 重检延期 / 报废），每条要给可行性、代价、评分、推荐。
3. **有人担**：报废与重检涉及资产，按金额 500 / 5000 分级审批，级别不够**后端直接拒**；做完必须留痕并关联真实单据号。

## 二、功能清单

| 能力 | 说明 |
| --- | --- |
| 临期三色 | 剩余效期（时间）+ 按日均消耗推算的预计用完日（数量）双维度判色：充裕 / 临期 / 已过期 |
| 消耗双口径 | 优先近 90 天已过账领用实测；样本 < 2 条改用「未完工工单 BOM 需求 ÷ 30 天」；两者都无则标「不可估」不预测 |
| 预计报废量 | 到期前用不完的数量与超出天数，以及对应金额 |
| 三方案 What-if | 提前排产消耗 / IQC 重检延期 / 报废处置，逐条给可行性、代价、评分与推荐 |
| 分级审批 | ≤500 元班组长、500~5000 元仓储主管、>5000 元生产经理；提前消耗 0 元免资产审批 |
| 兜底规则 | 已过期超过 15 天未处置 → 只剩「兜底报废」，评分 100 且唯一可行 |
| 处置留痕 | 每次决策落一条台账，关联废弃单（SCRAP-）/ 重检单（RI-）/ 优先消耗指令（PC-） |

## 三、关键设计取舍（评审可讲）

1. **判定权在规则，不在"感觉"** — 三色由「剩余效期 ≤ 类别阈值」或「到期前用不完」两条规则算，阈值按原料 30 / 辅料 20 / 其他 15 天，可调；不靠人猜。
2. **不拿假设值冒充预测** — 没有领用样本、也没有在手需求时，明确标「不可估」，不用行业均值硬算一个"预计用完日"。
3. **处置动作复用既有单据，不造第二套** — 报废走既有 `ScrapMaterial`（先写废弃台账→再改主表→数量归零），重检走既有 `ReinspectMaterial`。报废不可逆，绝不允许两份实现。
4. **临期批次不能"点一下就延期"** — 未过期批次的重检只登记「待 IQC」，效期只能由检验结论延长；已过期的才真延长（且写了重检台账）。
5. **分级审批真的会拦** — 班组长批 84,600 元的报废，后端返回"审批级别不足"，且零副作用（不写台账、不改效期）。
6. **兜底兜住"没人管"** — 过期超过 15 天仍未处置，重检方案自动判不可行，只剩兜底报废，避免账实长期不符。

## 七、已知限制

- 单价、临期阈值、兜底天数、重检延长天数均为**演示参数**，界面与口径已注明真实环境取自 ERP 物料主数据 / 质量协议。
- 「提前排产消耗」只登记优先消耗指令（`MaterialPriorityMark`），**不改排程引擎**——界面上已写明，避免夸大成"自动重排"。
- 日均消耗按物料维度（同物料多批次共享速度），实际领用按 FIFO 先出；批次级精确分摊需接入逐批领用明细。
- 审批角色是"岗位档位"下拉（班组长 / 仓储主管 / 生产经理），未接人员档案里的实际任职关系。
