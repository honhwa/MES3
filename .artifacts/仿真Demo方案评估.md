# 「仿真模拟 Demo 页」可行性评估

> 2026-10-26 | 仅评估，未改动代码 | 对象：`WebAssets/digital-twin/` 16 页 + MES3 数据层

## 一、结论

**能做，而且成本比想象低一个数量级。** 分三档：

| 档 | 范围 | 人天 | 周期（单人） | 适合场景 |
|---|---|---|---|---|
| **D1 演示加强版** | 现有页串成"演示模式"：统一入口 + 时间轴 + 暂停/加速 + 导演脚本 | **2** | 2~3 天 | 明天就要讲、讲 10 分钟 |
| **D2 统一仿真内核（推荐）** | 一份台账驱动全部页 + 时间加速 + 工单状态机真实流转 + 可重放 | **8** | 1.5~2 周 | 要经得起追问"这个数怎么来的" |
| **D3 业务可操作仿真** | D2 + 点得动的流程（派工→过站→报工→检验→入库）+ 异常注入 + 事件流 | **16** | 3~4 周 | 要演完整业务闭环、替代现场走查 |

**推荐先做 D2**：D1 好看但一旦被追问就露，D3 成本翻倍而演示现场往往用不到那么深。D2 是"真实感"的分水岭。

## 二、为什么便宜：已有资产盘点

| 资产 | 规模 | 状态 | 可直接用 |
|---|---|---|---|
| 16 个孪生页 | 约 11,000 行 HTML | 全部是 Web、零外链、离线可用 | ✅ |
| `MockSource → Store → View` 架构 | 每页统一 | 已有 Redux 风格单一数据源 | ✅ |
| 仿真推进循环 | `setInterval 3s → TICK` | 已在跑 | ✅ |
| 确定性随机 | `makeRng(seed)` | 同 seed 可复现 | ✅ |
| Canvas 2.5D 产线自绘 | production / device / warehouse 等 | 4 产线 + 设备三色 + 悬停面板 | ✅ |
| 指标累进口径 | 产量/良率/稼动，含三档折算 | 已按口径实现 | ✅ |
| Agent/问答弹药库、离线包机制 | `.artifacts/offline-package/` | 已有 | ✅ |

**真正缺的四件事**（这才是工作量）：

| # | 缺口 | 现状 | 影响 |
|---|---|---|---|
| 1 | **跨页台账不统一** | 每页各自 mock，工单号只在单页出现（`WO-2026-1015-020` 各 1 次） | 生产说 A 线在跑 020，切到仓储查不到这批 → 现场会被问穿 |
| 2 | **没有时间加速** | 3 秒 = 实时 | 讲"一个班 8 小时"要么等 8 小时，要么数字看不出变化 |
| 3 | **工单没有真流转** | `tick()` 是"快照式刷新"，数字在动，状态机没动 | 演示"这批货怎么从投料到入库"讲不连贯 |
| 4 | **没有导演脚本** | 需手工点菜单 | 汇报时手忙脚乱、遗漏关键页 |

## 三、D2 实施方案（推荐）

### 3.1 技术路线

```
                    ┌─────────────── sim-core.js（新增，约 800 行）───────────────┐
                    │  台账（工单/批次/设备/物料/质检） → 状态机 → 事件流 → 时间轴  │
                    └───────────────────────────┬───────────────────────────────┘
                                                │  SimCore.snapshot(t)
        现有 16 页  View 不动，只把 MockSource.tick() 换成读快照
                    production-twin / device-twin / warehouse-twin / quality-twin / carbon-twin …
                                                │
                                    ┌───────────┴───────────┐
                                    │  demo.html 演示控制台   │
                                    │  时间/倍速/场景/字幕    │
                                    └───────────────────────┘
```

**核心设计决定：视图层一行不改。** 每页数据源都是同一个 `MockSource.tick()`，改这里就换了全厂数据源，风险最低。

### 3.2 仿真内核要解决的四件事

| 能力 | 做法 | 演示价值 |
|---|---|---|
| **单一台账** | 一份 `SimCore`：8 张工单、12 批次、4 产线 20 台设备、物料/质检记录，全部带 id 与外键 | 任何页查同一批号，数字对得上 |
| **时间加速** | 内部虚拟时钟 `t`（分钟），倍速 1x/60x/600x；3 秒 tick 推进 `t += 3 × 倍速/60` | 3 分钟演完一个班 |
| **工单状态机** | `待下发→已下发→首件→过站中(各工序)→完工→待检→已入库→已出货`，每步有耗时与产出 | 能讲"这批货现在在哪" |
| **确定性可重放** | 全部随机走 `makeRng(seed)`；`重置` 回到 t=0 同一 seed | 演示翻车能原样重来；二次演示数字一致 |

### 3.3 工作量分解

| 项 | 说明 | 人天 |
|---|---|---|
| `sim-core.js` | 台账 + 状态机 + 事件流 + 虚拟时钟（约 800~1000 行） | 3.0 |
| 5 个主页面数据源适配 | 把 `MockSource.tick()` 改为 `SimCore.snapshot()`，视图不动 | 2.5 |
| `demo.html` 演示控制台 | 时间/倍速/场景切换/讲解字幕/一键重置 | 1.5 |
| 自洽性校验 | 同 seed 重放一致、跨页数字对齐、口径抽查 | 1.0 |
| **合计** | | **8.0** |

### 3.4 D1 / D3 与 D2 的差异

| | D1（2 人天） | D2（8 人天） | D3（16 人天） |
|---|---|---|---|
| 统一入口 + 自动播放 | ✅ | ✅ | ✅ |
| 时间加速 | 仅前端倍速（各页不同步） | ✅ 全页同步 | ✅ |

| 演示翻车可重放 | ❌ | ✅ | ✅ |

## 四、必须说清的边界（避免预期错位）

### 4.1 这是"演示型仿真"，不是"分析型仿真"

| | 演示型（本次方案） | 分析型（离散事件仿真 DES） |
|---|---|---|
| 目的 | **看着像真在跑**，讲得通 | **回答"如果…产能/交期会怎样"** |
| 内核 | 确定性随机 + 状态机 | 排队论 / 事件调度 / 资源约束求解 |
| 能答 | "这批货到哪了""今天产了多少" | "加一台化成柜，瓶颈移到哪""插单影响几天交期" |
| 成本 | **8 人天** | **35~60 人天**（且需要工艺节拍、良率分布、换型时间等真实参数，现在没有） |

如果你要的是后者（拿仿真结果做投资决策/产能规划），那是另一个项目，且**前提是先把真实工艺参数摸出来**——目前系统里的节拍都是模拟值。

### 4.2 三条硬边界

1. **纯前端，不连后端**：观众若要求"打开你们系统查一下"，这个 demo 给不出——它是演示件不是系统。
2. **数据自洽有深度上限**：能撑住 2~3 层追问（批号→工单→产线）。若问到"这批料的供应商上次送货日期"，需要台账再加一层，成本 +2 人天。
3. **不是"能用"，是"能演"**：不能真填数据、不能走审批、不能多人协作。

### 4.3 与"整体转 Web"的关系

本方案是上一轮评估里 **"只做看不做改的汇报版（20~30 人天）"** 的核心部分，但**更省**——因为 16 个孪生页已经做好了，8 人天只是把它们变成"一套会讲故事的仿真"。

如果后续要接真后端（MES3 的 C# 数据层包 API），`SimCore` 的接口（`snapshot()`）可以原样被真实 API 替换，**不会白做**。

## 五、建议

**做 D2，先做 3 天的最小闭环验证**：
1. 第 1 天：`sim-core.js` 台账 + 虚拟时钟
2. 第 2 天：production-twin 接通（跑起来能看到产量随虚拟时间累进）
3. 第 3 天：加 warehouse-twin 联动，验证"生产说在产的批次，仓储查得到"

三天后你能亲眼看到"跨页数字对得上"的效果，再决定是否继续做完 5 页 + 控制台。

**不建议一上来做 D3**：可操作仿真要处理大量异常分支，而汇报场景 90% 时间是"我讲你看"，用不上点击。

## 六、需要你确认的两件事

1. **演示场景**：是"展厅/会议室大屏自动播放（我讲你看）"，还是"要在电脑上点着操作给客户看"？→ 前者 D2 够，后者要 D3。
2. **是否要嵌进 MES3 桌面端**（现在孪生页就是内嵌 + 外链两种方式），还是纯浏览器独立演示？→ 纯浏览器更省，也方便发给别人。
