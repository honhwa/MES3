## 一、这一批解决了什么问题

齐套校验只能回答"缺多少"（缺铝壳 2842 只），但业务上真正要回答的是三件事：

1. **这批料是整个厂一起缺，还是某张单缺？** → 一级：跨工单需求合并
2. **扣掉库存、扣掉在途，到底还差多少？** → 二级：可用 / 在途 / 草稿 / 冻结 / 安全库存分列
3. **什么时候必须下单？现在下单赶得上开工吗？** → 三级：净缺口 + 采购前置期倒推最晚下单日

## 二、功能清单

| 能力 | 说明 |
| --- | --- |
| 缺料三级校验 | ① 需求合并（跨工单累加）→ ② 扣减（可用/在途/草稿/冻结/安全）→ ③ 净缺口 + 建议采购量 |
| 采购前置期 | 需求日 = 最早开工日 − 到货缓冲；最晚下单日 = 需求日 − (L/T + 检验缓冲) |
| 下单时点三色 | 逾期（红，已赶不上开工）/ 临近（橙，7 天内）/ 充裕（未着色） |
| 建议采购量 | (未覆盖缺口 + 安全库存缺口) × 1.10 → MPQ 向上取整 → 按「需求 ×1.2 与单次限额取小」钳制 |
| 自动建单 | 按开工先后生成采购申请草稿；含草稿去重、损耗/MPQ 调整、数量校验复核、空单丢弃 |
| 占用来源下钻 | 选中物料 → 列出哪几张工单、各占多少、生产时间窗、占用公式 |

## 三、关键设计取舍（面试/评审可讲）

1. **规则实时展开，不依赖台账是否已登记**
   资材占用台账要"登记过"才有数据。如果工单刚建、还没人点过登记，缺料校验会静默返回"没有缺口"——这比报错危险。所以一级需求按「未完工工单 × BOM」实时展开，公式与台账完全一致，且不写任何数据。
2. **草稿不算在途，但必须显示**
   系统口径里草稿/已驳回不算在途（货一定不会来），所以缺口仍然存在；但自动建单若不处理这点，第二张单会把第一张草稿已申请的同一批料再申请一遍（实测两单各 3500，合计 7000 > 实际缺口 2842）。做法：建单后按未提交单据覆盖去重，建议量按「未覆盖缺口」算，界面上草稿量单独成列并提示"草稿已覆盖，请去提交审批"。
3. **建议量先钳制再落单**
   MPQ 向上取整会把量抬高，抬过超量线就会在提交时被数量校验拦下。生成时就把量压回可提交区间，被钳制在行备注里写明，避免"建了单提交不了"。
4. **判定权在规则，模型不参与**
   本页所有数字由规则算出，没有 AI 判断；AI 库存分析（既有功能）只做措辞解读，建议量仍走规则钳制。

## 四、演示路径（F5 启动后）

1. 「仓储与出货 › 缺料三级校验」
2. 看 5 张卡：参与工单 3 / 涉及物料 8 / 短缺 2 / 已逾期下单 2 / 7 天内须下单 0
3. 第一行铝壳外壳：需求合并 3 张工单 7842.02 只 → 可用 5000、安全 1000 → 净缺口 2842.02 → 建议 3500 只（含损耗·MPQ）
4. 前置期 L/T 20 + 检验 2 = 22 天 → 需求日 08-09 → **最晚下单 07-18 已逾期 94 天**（红色）
5. 选中行下方看占用来源（3 张工单、时间窗、占用公式）；结论条给出处置建议（插单加急 / 让步接收 / 换料）
6. 点「⚡ 按缺口自动建单」→ 生成草稿并去重 → 到「资材采购申请」提交、审批、下单、完结入库
7. 回来再看：净缺口仍显示（草稿不算在途），但建议量变「—（草稿已覆盖）」，结论条提示去提交审批
