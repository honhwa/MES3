# 新产品「仿真测试」可行性评估与验证方案

> 2026-10-26 | 仅方案评估，未开发 | 对象：MES3 `sim-core` 仿真内核 + 新产品 NPI 场景

## 一、结论

**能做 demo，但"demo"和"验证"是两件事，成本差 5 倍。**

| 档 | 你得到什么 | 人天 | 能回答 | 不能回答 |
|---|---|---|---|---|
| **L1 演示级** | 新产品在产线上跑起来的动画画面 | **8 ~ 12** | "看着能上线" | 产能多少、瓶颈在哪、交期几天 |
| **L2 解析模型（推荐先做）** | 一张参数表 + 一个产能/瓶颈计算器 | **15 ~ 25** | 日产能、瓶颈工序、良率连乘 | 排队/在制/交期分布 |
| **L3 离散事件仿真（DES）** | 事件调度引擎 + 统计报告 | **35 ~ 60** | 交期分布、在制曲线、瓶颈漂移、插单影响 | 仍需真实参数才有意义 |

**关键判断**：如果你的目的是"新产品评审会上有个能演的东西" → L1 够，**8~12 人天**；如果是"新产品能不能上、要投多少钱" → 必须 L2 起步，且**前提是拿到真实工艺参数**（现在系统里全是模拟值）。

## 二、新产品仿真到底要回答什么（五个问题）

| # | 问题 | 决定什么 | 需要的模型 |
|---|---|---|---|
| 1 | 这条线**能不能做**（设备能力、精度、温区、洁净度是否兼容） | 要不要新设备投资 | 规则表（设备能力矩阵），不需要仿真 |
| 2 | **多快**（节拍 → 日产能） | 报价、承诺交期 | 静态公式即可（L2） |
| 3 | **卡在哪**（瓶颈工序、设备利用率、排队长度） | 加哪台设备最有效 | 需要排队模型（L2 近似 / L3 精确） |
| 4 | **良率多少**（各工序 FPY、报废/返工分布） | 成本、损耗 | 连乘模型（L2）；分布模拟（L3） |
| 5 | **什么时候能交**（交期、插单影响） | 接不接这个单 | 必须 DES（L3） |

**只做 L1 的话，五个问题一个都答不了**——它只是画面。

## 三、现有资产能复用多少

| 现有 | 状态 | 复用价值 |
|---|---|---|
| `sim-core` 虚拟时钟 + 停机窗口状态机 + 确定性随机 | 已可用 | **直接复用**（L1/L2 的骨架） |
| 节拍表（卷绕 6.8s / 涂布 9.4s / 装配 7.2s / 化成 22.5s / 注液 6.0s / 检测 4.2s） | **硬编码模拟值** | 结构可复用，**数值必须换成新产品的实测节拍** |
| 良率基线（97.6~99.8%） | 模拟值 | 同上 |
| 产量累进算法（有效运行分钟 × 速率） | 已可用 | L2 可直接用 |
| 排队 / 缓存 / 换型 / 瓶颈识别 | **完全没有** | L3 要从零做 |
| MES3 数据层（工艺路线、BOM、设备台账） | 有 | 可作为参数录入的基础 |

一句话：**骨架有了，参数是空的，排队模型没有。**

## 四、验证方案（如何判定仿真结果可信）

这是本方案的核心。仿真最怕"跑出一个漂亮数字，但没人敢用它做决策"。七道校验，缺一不可：

### 4.1 输入侧校验（参数可信吗）

| # | 校验 | 通过标准 |
|---|---|---|
| 1 | **参数来源留痕** | 每个节拍/良率/OEE 都标注来源（工艺文件编号 / 试产报告 / 实测日期），不接受"估计值"无标记 |
| 2 | **参数一致性** | 节拍 × 工位数 ≈ 实测产能（偏差 ≤10%），否则参数有矛盾 |
| 3 | **能力矩阵完整** | 新产品经过的每道工序，都有明确"现有设备可做 / 需改造 / 需新增"判定 |

### 4.2 模型侧校验（模型对不对）

| # | 校验 | 通过标准 |
|---|---|---|
| 4 | **历史回测** ★ | 用**已量产型号**的真实数据跑一遍，仿真 vs 实际：产能偏差 ≤5%，良率偏差 ≤2pp。**这一项过不了，其余结论都不可信** |
| 5 | **极端值校验** | ① 单工序产能设无限 → 全线产能 = 其余工序最小值；② 任一工序产能设 0 → 全线产出 0；③ 良率设 100% → 产出 = 投入 |
| 6 | **守恒校验** | 投入 = 良品产出 + 报废 + 在制（每个时刻都成立，不允许"凭空多出"） |
| 7 | **单调性校验** | 节拍变快 → 产能不能反而下降；OEE 提高 → 产出不能反而下降 |

### 4.3 输出侧校验（结论敢用吗）

| # | 校验 | 通过标准 |
|---|---|---|
| 8 | **敏感度分析** ★ | 节拍 ±10%、良率 ±2pp、OEE ±5% 各跑一遍，输出变化幅度合理且有排序（哪个参数最敏感要说得清） |
| 9 | **瓶颈交叉验证** ★ | 仿真识别的瓶颈工序 = 现场/IE 判断的瓶颈工序。不一致时必须能解释原因 |
| 10 | **专家评审** | 工艺 + IE + 生产三方看结果，"符合直觉"或"能解释为什么反直觉" |
| 11 | **可复现** | 同一份参数 + 同一 seed 重跑，结果完全一致（现有 `sim-core` 已具备该性质） |

### 4.4 交付物（验证报告要有什么）

1. 参数表（含来源与日期）
2. 模型说明（假设、简化、不适用场景）
3. 历史回测对比图（仿真 vs 实际）
4. 敏感度分析表（哪个参数最要命）
5. 结论与置信度（**必须写明"本结论基于 X 假设，若 Y 变化则结论失效"**）
6. 与试产计划的关系（哪些结论要靠试产验证）

> **必须写进报告的一句话**：仿真不能替代试产。它的价值是"减少试错次数、提前暴露瓶颈"，不是"证明能行"。

## 五、数据缺口（最大风险，建议先解决）

| 数据 | 来源 | 现状 | 拿不到会怎样 |
|---|---|---|---|
| 新产品工艺路线（工序序列 + 前后道） | 工艺部 | 部分有 | 仿真无法建模 |
| **各工序标准节拍（秒/只，含批量）** | IE / 工艺 | **缺（现为模拟值）** | 产能结论不可信 |
| **各工序良率 / FPY** | 试产 / 历史 | **缺（新产品没有）** | 良率与成本结论不可信 |
| **换型时间（型号切换）** | IE | **缺** | 多品种混线时会严重低估损失 |
| 设备能力矩阵（能否做新产品） | 设备 / 工艺 | 部分 | 问题 1 答不了 |
| **OEE / MTBF / MTTR（实测）** | 设备管理 | 现为模拟值 | 产能虚高 |
| 批量规则（如化成柜每批多少只） | 工艺 | 部分 | 交期与在制算不准 |
| 班次制度与有效工时 | 生产 | 有（8h 三班） | — |

**建议动作**：先建一张《新产品仿真参数表》（Excel 即可），把上表"缺"的逐项找工艺/IE 要。**这张表比任何模型都值钱**——没有它，L3 跑出来的数字没人敢用。

## 六、三档方案的具体做法

### L1 演示级（8~12 人天）— 能演不能算

| 步骤 | 内容 | 人天 |
|---|---|---|
| 1 | 把节拍/良率/工艺路线从硬编码改为**参数化**（新产品 profile） | 3 |
| 2 | demo 加「产品选择」下拉（老产品 / 新产品 A / 新产品 B） | 2 |
| 3 | 新产品专属视觉标识（如设备上加"NP"标记、图例区分） | 1 |
| 4 | 讲解字幕增加"新产品上线"一幕 | 1 |
| 5 | 自测 + 截图 | 2 |

**产出**：一个能演"新产品在产线上跑"的大屏。**适合评审会开场，但不能用来回答产能问题。**

### L2 解析模型（15~25 人天）— 能算，近似

| 步骤 | 内容 | 人天 |
|---|---|---|
| 1 | 参数表录入（工序/节拍/工位数/良率/OEE/换型） | 5 |
| 2 | 产能计算：`日产能 = 有效工时 × OEE ÷ 瓶颈节拍 × 良率连乘` | 3 |
| 3 | 瓶颈识别：逐工序产能排序，输出"卡在哪 + 加一台提升多少" | 3 |
| 4 | 与 L1 画面联动（改参数 → 大屏数字跟着变） | 4 |
| 5 | 报告导出（产能表 + 瓶颈图 + 敏感度表） | 4 |
| 6 | 历史回测 + 校验（4.2 的 4~7 项） | 4 |

**产出**：NPI 评审会上能给出"日产能 X 只、瓶颈在化成、加一台提升 Y%"的量化结论。**这是性价比最高的一档。**

### L3 离散事件仿真（35~60 人天）— 能算准，但要参数

| 步骤 | 内容 | 人天 |
|---|---|---|
| 1 | 事件调度引擎（工序排队、缓存上限、批量、换型） | 15 |
| 2 | 故障与维修建模（MTBF/MTTR 分布） | 6 |
| 3 | 统计输出（在制曲线、交期分布、设备利用率、瓶颈漂移） | 10 |
| 4 | 场景对比（A 方案 vs B 方案，如"加一台化成柜"vs"两班倒"） | 8 |
| 5 | V&V 全套（历史回测 + 敏感度 + 专家评审） | 10 |

**产出**：能回答"接这个单能不能按期交"。**建议等试产有实测数据后再上。**

## 七、建议路径

```
第 1 步（现在，1~2 天）
  └─ 建《新产品仿真参数表》骨架，标注"哪些有、哪些要找谁要"
       ↓ 这一步做完就知道能不能做 L2
第 2 步（2~3 周）
  └─ L2 解析模型 + 与现有大屏联动
       └─ 产出：评审会能用的产能/瓶颈量化结论
第 3 步（视需要，等试产数据）
  └─ L3 DES，用于产能规划与投资决策
```

**不建议一上来做 L3**：参数全是模拟值时，DES 跑得越精细，越容易给出"看起来很专业但站不住"的结论。

## 八、边界（必须讲清，避免预期错位）

| 能做 | 不能做 |
|---|---|
| 演示新产品上线后的运行画面 | 替代试产（实物验证） |
| 估算日产能、识别瓶颈、算良率连乘 | 保证 ±5% 精度（除非参数实测且历史回测通过） |
| 对比不同方案（加班/加设备/换线） | 预测具体某台的故障时间 |
| 提前暴露"某工序可能卡住" | 代替工艺验证（温度曲线、密封性等物理指标） |
| 作为评审会的量化依据（带置信度） | 作为对外承诺交期的唯一依据 |

## 九、与现有 MES3 的关系

- `sim-core` 的**虚拟时钟、停机窗口、确定性可重放**可直接复用于 L1/L2；
- L1 完成后再做 L2，边际成本只有 L2 的第 2~3 步（参数表与产能算法），因为画面已经有了；
- L3 的引擎与前端无关，可以独立做，结果再"喂"给大屏展示。
