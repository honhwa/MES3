feat: 新增现场无纸化系统（Excel/Word 点检表导入→在线填写→快照归档→电子档还原）

## 功能说明
新增第 9 个导航分类「现场无纸化」，含 3 个页面、101 个页签（原 98）：

1. 模板管理（paperless.template）
   - 导入 .xlsx / .docx 制作的点检表，零外部依赖（内置 ZIP+XML 解析）；
   - 按真实点检表版式四段切分：标题 / 抬头信息（车间·线别、点检日期、班次、
     温湿度）/ 表头 / 表体 / 表尾说明——抬头行不会被误当表头；
   - 纵向合并的分组列（如多行合成一个「静电防护(ESD)」）自动展开到每一行；
   - 按列头关键词推断列类型（上下文/文本/多行/数值/日期/下拉/勾选/签名），
     列头写 OK/NG 就给 OK/NG 两档，可在预览里手动调整类型与必填；
   - 导入后「表体预览」列出文件中的全部数据行，核对无误再保存。

2. 填写提交（paperless.fill）
   - 抬头字段单独渲染成输入框（占位取原表提示），表尾说明在底部只读提示；
   - 按列类型自动生成填写控件（下拉/勾选/文本，上下文列只读）；
   - 提交时校验必填/数值/日期，并把「提交时刻的模板完整快照」+ 填写值 + 抬头值
     一并归档。

3. 历史查询与电子档还原（paperless.history）
   - 按模板/填写人/日期区间/关键字检索（关键字覆盖填写值、设备、抬头值、
     表体上下文，现场按「静电防护」这类分组名也能查到）；
   - 双击记录以当时格式（抬头+表体+表尾）+ 数据完整还原「电子档」，
     列宽按内容自适应、可横向滚动不截断，填充单元格绿底高亮；
   - 支持导出自包含 HTML（含抬头表与说明）与打印。

## 核心设计：历史快照隔离
每条提交内嵌提交时刻的模板深拷贝快照（TemplateSnapshot，含 Columns/Rows/
HeaderFields/FooterNotes）。无论模板后来如何改名、加列、删列、改抬头、删说明、
甚至整模板删除，历史记录打开永远是填写那一刻的样子——这是无纸化系统对抗
「模板随业务演进」的关键保证。

## 同列多行批量填充（2026-10-20 追加）
现场一个人点检几十项，签自己的名字要写几十遍。三个入口，默认只写空白行：

  （全部行 / 仅空白行 / 仅选中行）；

## AI 语义复核 + 三色确认（P1，2026-10-20 追加）
定位：**默认走规则，模型只做增强**。模型未配置时入口置灰，规则解析结果照常可用。

- 复用既有护栏：给 LlmService.CallJson 增加可注入配置的重载，自测可用假配置 +
  假 HttpClient 跑真实链路（JSON 容错提取 / 业务校验 / 置信度门槛 / 失败降级）。
- 输入侧：把原始表压成带 R/C 坐标的紧凑文本（空单元格不输出、合并区域单列一行、
  超 200 行截断），每个值都带坐标——这是模型给 sourceRef 的唯一依据。
- 模型侧：强约束提示词（PromptVersion=paperless-sheet-v1）三条铁律——只许用原文、
  必须给 sourceRef、不确定标低置信不要猜。
- 校验侧四道核对：① 原文可溯 ② 完整性双向核对（规则列数 vs 模型列数，漏项/多项差集
  显式进提示，禁止静默合并）③ 类型双口径 ④ 位置合法性（坐标越界判红）。
- 三色确认页：绿=一致可直接采纳、黄=不一致/低置信/漏项待确认、红=原文找不到或越界
  疑似编造（不采纳）。点任一行右侧高亮模型给出的原文依据格。
- 两个安全默认：抬头字段**默认不替换**（模型少认时自动替换会丢项，必须人工勾选）；
  模型"多出来的列"不自动加列（原文有名字判黄、原文没这名字判红＝编造）。
- 缓存：SHA256(文件) + 模型名 + 提示词版本 → 同文件命中缓存零调用；可一键清空。
- 顺带统一口径：新增 FieldKindText 中英映射，列类型下拉与确认页由 Context/Select
  改为「上下文/选择」，与使用手册一致。


## 修复导入无反应 + 导入即 AI 解析（2026-10-20 追加）
徐工反馈导入「车间设备与环境班前点检表2.xlsx」界面没有任何反应。

根因两条（UI 探针量化证实，非猜测）：
1. 导入成功/失败都写到 `_lblFillStatus`——它属于「填写提交」页且不可见，
   用户在模板管理页零反馈；
2. `RefreshTplList()` 绑 DataSource 会让 DataGridView 自动选中首行并触发
   SelectionChanged，把刚导入待保存的预览顶成历史模板。

修复：
- 模板管理页新增本页状态栏（Dock=Bottom，两行高），导入/保存/删除/AI 全写它，
  导入后必定有文案（sheet 名 / 列×行 / 抬头 / 表尾）；
- 刷新列表时挂起预览切换标志，列表刷新不再覆盖刚导入的预览；
- 多工作表支持：ListSheets 按 workbook.xml + rels 解析真实路径（不再硬编码
  sheet1），>1 个 sheet 时弹「选择要导入的工作表」——台账/追踪表不是点检表；
- 状态栏区分「0 列」与「0 行」：0 行时说明是空白台账/待填表。

导入即 AI 解析（按要求重构）：
导入 → 规则解析立即上屏 → 模型已启用则自动追问大模型 → ApplyTo 后把 AI 解析出的
列/字段类型/抬头直接同步到界面 → 列定义表新增「AI 校验」列 + 行三色底 + 悬停给
依据位置与原因 → 摘要行显示「🤖 AI 解析：🟢N 🟡M 🔴K」→ 保留「查看 AI 复核详情」
进三色确认页逐项核对。规则基线单独保存（不能拿 AI 结果当基线再比一次＝自我印证）。

顺带修一个真解析缺陷：原「非空≤1 就当表尾」会把只预填序号列（1、2、3…）的空白
记录表整张切断，异常问题追踪表因此变成「0 行数据 + 20 条表尾说明」。改为只在尾部
认说明行（非空≤1 且该格≥8 字，且该行到末尾都满足）→ 追踪表恢复 10 列 × 20 行。

缓存 key 补 sheetIndex，避免同一文件不同 sheet 混用缓存。

自测：编译 0/0；.verify_fix 40/40 PASS，其中端到端真链路实调模型：
「AI 解析完成并已同步到界面（置信度 90%，耗时 2740ms）：🟢10 🟡0 🔴0」。

## 修复「Excel 尾部汇总行导致 DataGridViewComboBoxCell 值无效」（2026-10-20 追加）
现象：导入带汇总行的点检表后弹系统错误框 `DataGridViewComboBoxCell 值无效`。

定位：表尾「本班点检结果汇总（自动统计）｜0 项 OK｜0 项 NG」是三块合并单元格，
非空 3 格，逃过了"全空行"和"稀疏长文本"两条判据 → 被当成第 45 条数据行；
其中「0 项 OK」正好落进「点检结果」下拉列（候选只有 OK/NG）→ WinForms 抛 DataError。

两层修复：
1. 解析层剥离汇总行：表体边界确定后，对尾部最多 2 行识别汇总行
   （非空≤3 且首格含 汇总/合计/总计/小计/统计/累计/平均）→ 从表体剥离、归入表尾说明，信息不丢。
   表2：45 行 → 44 行，表尾 2 → 3 条。
2. UI 层防崩（通用，不只针对汇总行）：
   - 下拉列赋值前按 Options 判定，值不在候选集就不预填（留空让人选），
     不再把「0 项 OK」「—」塞进 ComboBoxCell；
   - _gridFill / _gridTplPreview 都挂 DataError（e.ThrowException=false + 状态栏提示），
     任何类型不匹配只提示不弹系统框。

自查抓到自己引入的 bug：汇总行被重复收进表尾两次（剥离后表尾循环仍从原起点扫）→
加 bodyEndRaw 记录剥离前起点修正。

自测：编译 0/0；.verify_sum 24/24 PASS（含"故意造非法下拉值模板不崩"、
合法值仍正常预填、非法值均留空、手工塞非法值被兜住且状态栏提示、
表1 仍 23 行 / sheet3 仍 20 行 未被误剥）。

四个 WebView2 坑（实测踩过，已修）：
1. 原生 WebView2Loader.dll 默认不复制到输出根目录 → 用 GeneratePathProperty + None Link 显式复制；
2. 非当前 TabPage 里初始化必失败（无句柄）→ 改成首次可见时初始化；
3. 必须在消息泵回调里发起初始化（BeginInvoke），否则报 "can only be accessed from the UI thread"；
4. 不要预先 await CoreWebView2Environment.CreateAsync —— 那步本身丢 UI 上下文，反而更坏。

## 修复模板导入失真 + 新增手写签名（2026-10-21 追加）

以徐工提供的 LibreOffice 导出 HTML 为权威基准，定位到两处真失真（都在渲染层，数据层早已正确）：

1. 列宽换算硬编码 MDW=7（px=w*7+5），只对 Calibri 11 成立。原表默认字体为宋体 11pt，
   真实 MDW≈8.2 → 整表偏窄：C 列（点检内容及标准）299px vs 原件 344px（差 45px）。
   修法：改用规范公式 px=⌊(256w+⌊128/MDW⌋)/256×MDW⌋，MDW 按默认字体推（CJK 8.2/西文 7）。
   修完 10 列宽度与参照逐个一致（49/131/344/131/82/164/98/180/82/82）。

2. ★ style="font-family:"Noto Sans CJK SC",..." 里的双引号把 style 属性提前截断，
   整串内联样式（边框/底色/字色）全部失效 —— 画面上完全没有网格线和表头深蓝底。
   而旧断言只查"HTML 字符串里有 border-top"，全绿但画面全坏。
   修法：字体栈与字体名改用单引号并清洗引号；去掉与参照不一致的额外页头
   （原表首行本身就是居中标题）；去掉 overflow:hidden；未设 ht 的行改用
   sheetFormatPr@defaultRowHeight。

手写签名（新增）：签名列 = 隐藏域 + 可点区域，点击弹手写板（canvas，鼠标/触摸，DPR 缩放），
确定后 toDataURL('image/png') 写回隐藏 input，与普通输入走完全相同的 collect→归档链路；
只读归档渲染成 <img>，自包含落盘，打印/导出/重开均正常。
