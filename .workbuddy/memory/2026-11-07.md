# 2026-11-07

## WinForms 控件初始化迁移至 .Designer.cs（设计师相容改写）

- 起点：全项目 0 个 `*.Designer.cs`、0 个 `InitializeComponent()`；UI 全在建构式 / `Build*Tab()` 以程序码建立。
- 需求确认（AskUserQuestion）：迁移深度 = **设计师相容改写**；范围 = **Forms/ + MainForm 全部**。
- 实作模式（两档拆分）：
  - `<Class>.Designer.cs`：`#nullable disable`、`partial class X`、`IContainer components`、`Dispose(bool)`、`InitializeComponent()` 只含 Designer 可解析的宣告式陈述（new / 属性 / Controls.Add / Items.AddRange / TabPages.Add / ColumnStyles / RowStyles / 方法群事件 / Suspend-ResumeLayout）+ 所有控件栏位宣告。
  - 原 `.cs`：改 `partial`，建构式 `InitializeComponent(); InitializeRuntime(原参数);`；动态逻辑（DB 取数、回圈、插值、lambda、工厂、`DataGridViewCellStyle`、`Columns.Add`、条件着色）留 `.cs`。
  - 关键坑：原码 `Location = new Point(bottom.Width - 232, 10)` 在控件加入 `Controls` **之前**求值；.NET 10 `Panel` 预设宽 = 200（已用独立 probe 验证），故换算成 `-32 / 94` 等常量并加注，否则行为漂移。
  - 关键坑：事件若在 `InitializeComponent()` 过早挂上，`SelectedIndex/Text/Checked` 赋值会提前触发 handler 改写初值 → 敏感事件保留在 `.cs` 原顺序位置。
  - `readonly` 状态栏位移到 `InitializeRuntime()` 会 CS0191，须去 `readonly`；移到建构式外的非 nullable 栏位需初值或 `null!`，否则 CS8618（基线要求 0 警告）。
- 范围结果：**42 份 Designer.cs**（Forms/ 37 + 根目录 MainForm 1 + 4 个内嵌对话框）+ 37 份 `.cs` 改写。所有 Form 类别（40 个）都能无头建构。
- MainForm：`MainForm.Designer.cs` 含窗体属性、顶层 `_tabs`、底部自动刷新状态栏（StatusStrip + 7 ToolStripItem）、`_autoTimer`；`MainForm.cs` 建构式缩为 `InitializeComponent() + InitializeRuntime()`，后者保留 ~70 行 `RegisterPage(...)` 与 `AssistantEngine.Backend` 设定。
- **未完成**：47 个 `MainForm.*.cs` 分部档的 `Build*Tab()` 仍在执行期建立 57 个 TabPage 内的控件（约 2.1 万行）。C# 不允许把 `InitializeComponent()` 拆到多个档案，若要让设计师看到全部页签内容，需把整段 in-line 进单一 `MainForm.Designer.cs`，属独立大型批次。
- 验证工具：
  - `.artifacts/wf_designer_spec.txt`：迁移规格（后续批次沿用）
  - `.artifacts/check_designer.py`：静态检查 InitializeComponent 禁用语法 / BOM / #nullable disable / Dispose / canonical 颜色 / 栏位宣告。42/42 通过、exit 0。
  - 无头 smoke test（/tmp/wfsmoke）：反射建立全部 40 个 Form，OK=40 FAIL=0；MainForm 10 个一级分类 / 57 个二级页签。
- 结果：`dotnet build -c Debug` **0 warning / 0 error**（基线同为 0）。
