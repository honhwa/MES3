## 访问方式

> 演示大屏见下方「仿真演示大屏」章节：直接双击 `demo.html` 即可自动播放。

从 MES3 左侧导航 **「数字孪生」** 分类进入，默认提供两种打开方式：

1. **新标签页打开**（默认，零依赖）
   浏览器直接打开本地 HTML 文件，适合演示、投屏、双屏投放。
2. **内嵌展示**（需启用 WebView2，见下方）
   在 MES3 窗体内部嵌显示，适合一体机大屏。

两个孪生页右上角/左上角均有「← 返回运营大屏」，大屏内也可跳回设备/网络孪生页。

## 内嵌模式（WebView2）说明

内嵌需要 `Microsoft.Web.WebView2` 包。若项目未引用该包，MES3 会**自动降级为新标签页打开**并在界面上给出提示，不会报错或崩溃。

启用方式：

```powershell
dotnet add package Microsoft.Web.WebView2
```

添加后重新构建，入口页的「内嵌展示」按钮即自动可用。

> 运行时还需系统已安装 **Microsoft Edge WebView2 Runtime**
> （Win11 / Win10 21H2 及以上通常已随 Edge 预装）。

## 目录与部署

页面文件会随构建复制到输出目录：

```
bin/Debug/net10.0-windows/WebAssets/digital-twin/*.html
```

`SuperCapMES.WinForms.csproj` 中通过 `WebAssets/**` 的 `Content` + `CopyToOutputDirectory` 项保证
"复制到输出目录"。因此**直接运行 exe 或从 VS 启动都能找到页面**，不依赖源码目录。

## 在 MES3 中的集成方式

### 入口与位置

在「数字孪生」导航分类的入口卡片列表里，`demo.html` 排在**第一个**（`MainForm.Twin.cs` 的 `TwinPages[0]`），标题「仿真演示（四模块联动）」，图标 🎬。

放首位的原因：它是对外演示的主入口——一进来就自动播放，不需要逐个点开页面。

### 两种打开方式（沿用既有通道，未新增机制）

| 方式 | 行为 | 适用场合 |
|---|---|---|
| **内嵌展示** | `Source = new Uri(本地路径)` 在 MES3 窗体内的 WebView2 中打开；顶部有「← 返回入口列表」「↗ 改用浏览器打开」 | 会议室/工位讲解，切模块不出窗 |
| **新标签页打开** | 系统默认浏览器打开同一文件 | 展厅大屏（可 F11 全屏、投屏到电视墙） |

内嵌是**三层结构**：WebView2（MES3 窗体）→ `demo.html`（播放器）→ `iframe`（当前场景的孪生页）。
`iframe` 用**相对路径**加载同目录文件，所以必须走 `Source = URI` 导航（不能用 `NavigateToString`，否则相对路径失效）——MES3 现有实现正是前者，已核实。

### 加载哪些页面

| 层级 | 页面 | 作用 |
|---|---|---|
| 第 1 层 | `demo.html` | 播放器：时钟、班次进度、倍速、暂停/重置/全屏、右侧指标与事件流、底部字幕、四模块切换 |
| 第 2 层（iframe，同一时刻只加载 1 个） | `production-twin.html` / `warehouse-twin.html` / `quality-twin.html` / `device-twin.html` | 四个业务模块视图 |
| 第 3 层（被各页引用） | `sim-core.js` | 统一仿真内核：一份台账 + 一条虚拟时钟 |

> 四个模块页同时**也仍是独立的孪生入口**：从卡片列表直接点开某一页，它同样走 `sim-core`（页面自己带 script 标签），画面与 demo 内一致，不会出现"两套数据"。

### 加载后的交互与数据联动

| 联动项 | 效果 |
|---|---|
| **统一台账** | 4 产线 / 20 台设备 / 8 张工单是唯一真相源。生产页说在产 `WO-2026-1026-001`，仓储的齐套看板、质量的检验记录、设备的健康视图**是同一张单、同一批次**（`LOT-20261026-A~H`） |
| **虚拟时钟** | 顶部时钟 = 班内时刻（08:00 起）。倍速 60×/300×/600× 一次设置四页同步；暂停/重置同理（父页每 400ms 用 `postMessage` 广播，子页 `Clock.set()`） |
| **切模块** | 舞台左上角四个按钮，点击即换 iframe 的 `src`，并自动带上当前 `seed` 与虚拟时刻——**切过去不会退回 08:00** |
| **指标与字幕** | 右侧指标（产出/达成率/良率/设备三态）与底部 6 幕字幕由父页直接读内核计算，与主区画面同源 |
| **可重放** | 同一 `seed` + 同一虚拟时刻 → 四页画面完全一致。演示翻车可按 `R` 原样重来 |
| **URL 直达** | `demo.html?seed=1015&t=620&speed=600` 可指定"哪一天、从几点开始、多快"；单页也支持同样参数 |
| **键盘** | `空格` 暂停/继续、`R` 重置、`F` 全屏 |

### 已知限制

- 内嵌时 `iframe` 在 `file://` 下**不能跨 frame 读 DOM**（同源策略），所以父子间用 `postMessage` 通信，不用 DOM 访问；
- 纯前端仿真，不连后端——它是演示件，不是可操作的系统（观众要求"打开系统查"给不出）；
- 其余 12 个孪生页尚未接入 `sim-core`，接入方式见下节「两种接入形态」。

## 仿真演示大屏（demo.html + sim-core.js）

面向**展厅大屏自动播放**（"我讲你看"）与**纯浏览器独立演示**，不依赖 MES3 桌面端、不起服务器，双击 `demo.html` 即播。

### 文件

| 文件 | 作用 |
|---|---|
| `demo.html` | 演示控制台：虚拟时钟、班次进度、倍速（60×/300×/600×）、暂停/重置/全屏、右侧关键指标与实时事件流、底部 6 幕讲解字幕；主区用 iframe 承载孪生页 |
| `sim-core.js` | **统一仿真内核**：一份全厂台账（4 产线 / 20 台设备 / 8 张工单）+ 虚拟时钟 + 停机窗口状态机 + 事件流 + 确定性随机 |

### 为什么要有 sim-core

原来各孪生页各自内置 mock，**每 3 秒掷骰子决定设备状态** → 状态乱跳、产量忽高忽低、跨页数字对不上、讲不通。`sim-core` 把三件事一次性解决：

1. **状态由"停机窗口 + 虚拟时间"决定**，不是每拍随机。所以"09:20 张力波动报警、09:47 恢复"可以照着讲，产量曲线单调平滑。
2. **一份台账驱动所有页**。生产页说在产的批次，仓储/质量页查得到同一批号。
3. **确定性可重放**。`snapshot` 只依赖 `(seed, 虚拟分钟 t)`，不依赖调用次数 → 同一 seed 同一 t 必得同一画面，演示翻车可以原样重来。

### 接入方式（现有页面只改 1 行）

在页面 `</script>` 之后加一行：

```html
<script src="sim-core.js"></script>
```

`sim-core` 会接管 `MockSource.tick()` 与 `snapshot()`，**视图渲染代码一行不改**。sim-core 缺失时页面仍按自带 mock 独立运行（向后兼容）。

> 注意加载顺序：必须在页面自身脚本（`const MockSource = {...}`）**之后**，否则拿不到 `MockSource`（`const` 不挂 `window`，且在 TDZ 内 `typeof` 会抛错）。

### 时钟同步（file:// 下的关键约束）

Chrome 把每个 `file://` 视为独立不透明源，**父页无法读 iframe 的 DOM**。因此：

- **首帧**：`demo.html` 把 `?seed=&t=&speed=` 拼进 iframe 的 `src` 做对齐；
- **持续**：父页每 400ms `postMessage({type:'sim-clock', t, speed, paused})`，子页监听后 `Clock.set()`。`postMessage` 不受同源读限制，file:// 下可用。

### 已接入的四个模块（覆盖"生产 → 质检 → 入库"闭环）

| 模块 | 页面 | 接入方式 | 受内核驱动的内容 |
|---|---|---|---|
| **产线运行** | `production-twin.html` | A 类：整体换 `tick()` | 设备三色状态、在制工单、产量/良率/稼动累进、异常事件流 |
| **仓储库位** | `warehouse-twin.html` | B 类：接管 `_rng` + `series` + 批号工单号 | 库位占用/待检/锁定、库存金额与可用占比、出入库流水曲线、齐套看板工单 |
| **质量与 SPC** | `quality-twin.html` | B 类：同上 | 良率 / 一次交检合格率 / 缺陷 PPM、各线质量、缺陷分布、SPC 控制图 |
| **设备健康** | `device-twin.html` | B 类：同上 | 在线率、预警/严重台数、MTBF / MTTR、设备监控参数 |

**四个模块之间的关联**（演示时的串讲逻辑）：

```
产线运行  ── 谁在生产、在产哪张工单、产出多少
   │  工单 / 批次号（台账唯一真相源）
   ├──▶ 仓储库位  ── 这批料/成品在哪个库位、库龄多少、齐套能否投产
   ├──▶ 质量与SPC ── 这批的良率、缺陷 PPM、是否触发控制图越限
   └──▶ 设备健康  ── 生产这些货的设备是否健康、MTBF/MTTR 是否恶化
```

四页共用同一份台账（4 产线 / 20 台设备 / 8 张工单）与同一条虚拟时钟，所以：

- 生产页说在产 `WO-2026-1026-001`，仓储页的齐套看板、质量页的检验记录**是同一张单**；
- 暂停/加速/重置在 `demo.html` 上操作一次，四页同时生效；
- 同一 `seed` + 同一 `t` 重开，四页画面完全一致（可复现）。

### 两种接入形态（新页接入时照此判断）

| 形态 | 特征 | 接法 |
|---|---|---|
| **A 类** | 数据整体由 `tick()` 返回（生产页） | 直接覆盖 `tick()/snapshot()` 返回内核快照 |
| **B 类** | 有自己的 `_build()` 与 `series()`（仓储/质量/设备） | **不重建**，只接管 `_rng`：每次 tick 前重置为 `f(seed, 虚拟分钟)`；同时把 `series()` 的 X 轴换成虚拟时钟、把 `batch/lot/wo` 统一到台账 |

B 类的关键点：`_rng` 原本是**有状态**的（第 N 次 tick 的结果依赖调用次数），不重置就无法重放；而 `series()` 原本用 `Date.now()` 做 X 轴，不换就会"曲线与实时值打架"。

页面用 `<script>window.__SIM_PAGE = 'warehouse';</script>` 显式声明类型，避免靠特征猜测误判。

> 已接页面会带 `data-sim="warehouse"` 等标记（`document.documentElement`），无视觉影响，仅供自测确认。

### 键盘快捷键（演示时用）

| 键 | 作用 |
|---|---|
| `空格` | 暂停 / 继续 |
| `R` | 重置回 08:00 |
| `F` | 全屏（大屏演示必用） |

舞台左上角有**四个场景按钮**（产线运行 / 仓储库位 / 质量与SPC / 设备健康），点击即切页，切页时自动带上当前虚拟时钟——讲到哪看到哪，不用退出重开。

### 常用 URL 参数

| 参数 | 说明 | 示例 |
|---|---|---|
| `seed` | 仿真种子，换一个就是"另一天" | `?seed=1015` |
| `t` | 起始虚拟分钟（480 = 08:00） | `?t=620` → 从 10:20 开始 |
| `speed` | 倍速，1 实秒 = speed/60 虚拟分钟 | `?speed=600` → 48 秒演完 8 小时班 |

演示建议：**`?speed=60`**（8 分钟演完一个班，节奏适合讲解）；赶时间用 `300`。

## 修改页面后的生效方式

页面是纯静态文件，**改完直接重新构建即可**（或手动拷到 `bin/.../WebAssets/digital-twin/` 立即生效，无需重启 MES3）。

页面本身零外部依赖（不引 CDN、不引图表库），可单独双击打开用于独立演示。
